## 1. Clean-Source Rule

Future work begins from the restored pre-trial project sources and **fresh inspection of original evidence**. Do not recreate, quote, summarize, or use deleted post-trial scripts, campaign plans, framework translations, intelligence strategy sections, or analysis documents as precedent.

The raw evidence archive at `/home/ubuntu/pharma-script-gen-raw-evidence-archive-2026-09-01/` is **not an active script-writing source**. It exists only to recover original URLs, physical-label text, study links, first-party performance data, and other factual source records that must be re-opened and reassessed before use.

## 2. Active Writing Standard

The project retains the restored pre-trial framework and creator-analysis system. A script must follow the selected, source-validated framework's actual hook, section order, pacing, visuals, proof behavior, product placement, and CTA mechanics.

The sole standing protection applied during writing is **sentence-level qualification**. Use natural qualified language where appropriate, such as "may help," "helps support," "can help," "is used to help," or "has been studied for." Do not replace the viewer payoff, pharmacist explanation, direct benefit, proof strategy, pain point, or framework mechanics with defensive narration. The creator will make final filming, visual, caption, and posting decisions.

## 3. Just-in-Time Source Loading

Load only the sources required for the immediate task.

### Context-Reset Control

If working context has been compressed, reset, or otherwise cannot reliably retain the full text of a critical document, **stop the task at that point**. Reload the governing document(s), source logs, product facts, original media/source material, and quality or protocol controls required for the next action before analyzing, documenting, or drafting. A prior summary or recollection does not substitute for a fresh read of a critical active source.

| Immediate task | Required active sources |
|---|---|
| New product fact sheet | `MASTER_CONTEXT.md`, the current fact-only research protocol document (see Section 5 status note on `FACT_ONLY_PRODUCT_RESEARCH_PROTOCOL.md`), official product/listing/label sources, primary evidence relevant to actual claims, and the active Competitive Decision Map where a decision format is contemplated. |
| Creator or viral-format analysis | `MASTER_CONTEXT.md`, creator-onboarding/video-analysis instructions, the relevant existing hook framework, and the original video(s). |
| Script drafting | `MASTER_CONTEXT.md`, all six full writing references, the relevant framework/template, the current fact-only product sheet, source links, and any user-approved campaign plan. |
| Script revision | The same script-drafting sources plus the original script and the user's precise feedback. |
| Performance review | `MASTER_CONTEXT.md`, the user's actual metrics, the original video/script, and the performance-analysis framework. |

When a task spans multiple source types, reload the relevant source set **at the transition** rather than carrying rules across a compression boundary. For example, creator-video analysis requires its original video and source log; product intelligence requires the current research protocol and primary product sources; script drafting requires the six full writing references and the approved fact-only product record.

## 4. Rebuild Contract

No post-trial asset is automatically recreated. Rebuild in this order:

1. Reinspect original creator videos and create a framework record that preserves the real execution mechanics.
2. Reinspect official product pages, physical labels, studies, TikTok Shop listings, and genuine shopper evidence to create a **fact-only** product record.
3. Present a campaign plan for approval.
4. Draft one approved script or a specifically approved package using the loaded sources.
5. Record only user-confirmed filming and performance outcomes.
