# Clean-Slate Rebuild Plan

**Prepared:** September 1, 2026  
**Active baseline:** `0392bcdf`  
**Writing constraint:** **No new or reconstructed scripts until the final phase.**

## Purpose

The selective reset intentionally removed post-trial generated writing and guidance rather than treating it as reliable precedent. This plan rebuilds only the parts needed for future work, in dependency order, from the restored pre-trial system and fresh primary sources. It does **not** recreate removed material from memory, old generated copy, or archived strategy interpretations.

The lone standing writing protection is **natural sentence-level qualification** where appropriate. It may scope a claim, but it may not weaken or replace a proven creator structure, direct viewer payoff, pharmacist education, product benefit, pain point, proof behavior, or CTA.

## Rebuild Principles

| Principle | Operational rule |
|---|---|
| **Source first** | Reopen original creator videos, official listings, physical labels, studies, and user-supplied metrics before creating a new active conclusion. |
| **Facts separate from strategy** | Maintain a fact-only source record before any campaign or script recommendations. |
| **Framework fidelity** | Capture the actual hook, beat order, visual rhythm, proof-card behavior, product placement, and CTA mechanics—not merely the topic. |
| **Approval gates** | Present framework and campaign decisions before advancing into their downstream use. |
| **Just-in-time loading** | Load only the authoritative sources required for the immediate rebuild step. |
| **No silent carryover** | A deleted post-trial output cannot reappear as an example, default, or implied decision. It must be rederived from raw sources. |

## Proposed Sequence

### Phase 0 — Freeze the Clean Baseline

**Objective:** Confirm the reset boundary and create a durable, simple operating map before new analysis begins.

The active source set is the restored `0392bcdf` project plus `CLEAN_SLATE_ACTIVE_SOURCE_MAP.md`. The external raw-evidence archive is reference-only, not active writing guidance. Any fact recovered from the archive must be traced back to its original link, product label, video, metric screenshot, or first-party source before it becomes active again.

**Gate:** User confirms that the clean baseline, external archive boundary, and sentence-level qualification-only policy remain the standing operating model.

### Phase 1 — Rebuild the Creator and Framework Foundation

**Objective:** Rebuild only the formats that will be used soon, directly from the original creator examples.

Start with the highest-priority frameworks used across product campaigns:

1. **Short negative-apology BOF format** — exact misdirection, three-benefit stack, price/offer reveal, and CTA behavior.
2. **Long pharmacist-education apology format** — exact distinction from the short version, including where education belongs and how the viewer stays curious.
3. **Instruction-correction format** — source-verified use sequence plus the pharmacist-only reason each step matters.
4. **Scam-warning format** — four-item opening, fake-to-real pivot, educational middle, verification close, and the evidence required to call a listing fake or a scam.
5. **Bundle routine walkthrough** — rewatch the original bundle examples and document the full application/order teaching structure instead of relying on the deleted translation.
6. **Category scorecard / ranking adaptations** — rebuild only after fresh analysis of the original source video(s) and current category alternatives.

For each framework, create one **source-backed framework card** with: direct reference link, full-view observation notes, spoken/visual/text hook, timeline, visual overlays, proof strategy, product reveal timing, CTA, reusable mechanics, product-specific variables, and disallowed assumptions.

**Gate:** Present each framework card for approval before marking it active. Do not write product scripts while a framework remains unapproved.

### Phase 2 — Rebuild the Campaign Operating System

**Objective:** Restore the campaign planning sequence without importing post-trial campaign choices.

Rebuild the campaign-planning section of the product research protocol from the pre-trial template and approved framework cards. Every new product begins with:

| Required campaign stage | Rebuild requirement |
|---|---|
| **Product content benchmark** | Inspect the top 3–5 eligible exact-product videos available at research time. Capture actual hooks, visual treatment, format, runtime, reveal timing, proof behavior, CTA, visible engagement, and genuine questions. Do not infer sales from view count alone. |
| **Campaign plan** | Select the formats that match the product’s actual benefits, shopper pain points, category alternatives, visual demonstration potential, and verified product facts. |
| **Initial campaign suite** | Include the verified launch/MOF assets plus the standard BOF suite: short apology, long pharmacist-education apology, instruction correction, and scam-warning where factually supportable. |
| **Filming-day variables** | Mark live price, sale, availability, blue checkmark location, current listing/seller context, and any actual counterfeit evidence as variables that must be confirmed before filming. |
| **Performance plan** | Identify the test question for each asset and the exact 48-hour metrics needed to evaluate it. |

**Gate:** Present the campaign sequence and filming-day variables for approval before drafting scripts.

### Phase 3 — Rebuild Fact-Only Product Intelligence, One Product at a Time

**Objective:** Create fresh, source-traceable product records without importing prior strategic interpretation.

The next intel document should use the full protocol and contain only:

1. Exact product identity, current seller/listing, price/variant, and a copied source URL.
2. Full package/official-label facts, including complete ingredients, directions, warnings, and manufacturer information where available.
3. Verifiable product claims and clear source attribution in the **research record**, not in spoken scripts.
4. Ingredient evidence with the actual study population, endpoint, limitations, and a clear distinction between ingredient research and product-formula research.
5. Real category competition: common alternatives, their honest strengths and limitations, and why the target product may suit a defined viewer/use case.
6. Genuine observed shopper questions, objections, and creator-content observations—with sample size and access limitations stated plainly.
7. A source map showing exactly which facts are suitable for future product education, which require qualified language, and which cannot be carried into a script.

The product record should not decide whether a line is “safe enough,” dilute a benefit, or invent a campaign angle. It supplies the verified inputs for the separate campaign-planning stage.

**Initial priority:** Rebuild **Dr. Dent Purple Toothpaste Tablets** from its original TikTok Shop link, the user-supplied physical label, official product sources, directly opened creator videos, and reopened primary evidence. The archived label transcription and image files are pointers only; the physical-label facts must be confirmed directly from the original images again.

**Gate:** Present the fact-only Dr. Dent record for approval before creating its fresh campaign plan.

### Phase 4 — Rebuild Priority Product Campaign Plans

**Objective:** Apply the approved frameworks and fact-only intel records to product-specific, user-approved content plans.

Begin with Dr. Dent only after Phases 1–3 are complete. Build a new campaign sequence from its fresh product record and the approved framework cards. The campaign plan must state why each format is the right match for the product, the viewer pain or desired outcome, product benefits to explain, proof visuals, exact timing of the unresolved question and verdict, buyer-psychology levers, actual CTA option, and filming-day checks.

Then repeat this product-by-product for future priorities. Do not create a broad batch campaign plan before each product’s sources are freshly inspected.

**Gate:** User approves the product-specific campaign plan before any script is drafted.

### Phase 5 — Rebuild Performance and Learning Records

**Objective:** Preserve real learning without importing post-trial interpretations as rules.

Re-enter only user-confirmed metrics, actual filming status, and unambiguous factual outcomes into an active performance log. For any video made after `0392bcdf`, recover the raw metric inputs from the external archive or user-provided screenshots and reanalyze the original script/video as a new exercise. Do not reuse the deleted conclusion automatically.

The first performance reconstruction priority is the actual 48-hour data for the Medicube NEVER/ALWAYS test, TX Cream Tier-List, Magnesium Tier-List, and any other user-confirmed posts that will affect future framework choices. Every conclusion must be explicitly labeled as a new analysis of the raw data.

**Gate:** User reviews the new result summary before a performance conclusion becomes a permanent framework change.

### Phase 6 — Script Writing — Final Step

**Objective:** Write new campaign scripts only after approved framework cards, a fact-only product record, and an approved campaign plan exist.

Before script writing, load the six full writing references, the relevant approved framework card, the fact-only intel record, original source links/studies, the approved campaign plan, and the exact product/listing proof. Each script must use the selected framework as analyzed; deliver a concrete viewer pain or desired outcome; explain the reason to care in normal language; use direct benefits; deploy proof cards where the source format supports them; preserve curiosity; and use appropriate sentence-level qualification without weakening the script.

The initial script output is a **single approved first asset**, followed by review and adjustment before a full campaign batch. Scripts are intentionally last in this plan.
