# Campaign Structure Status — Active vs. Legacy Protocol

**Purpose:** Reconcile the older `PRODUCT_RESEARCH_PROTOCOL.md` campaign-structure section with the active clean-slate product-research system before the Claude Project knowledge base is finalized.

**Scope:** This is a documentation-status assessment. It does not approve a campaign, change the active campaign rules, or create scripts.

> **Conclusion:** The former “Step 12 — Content Campaign Plan” is **not current as a whole**. The active `FACT_ONLY_PRODUCT_RESEARCH_PROTOCOL.md` intentionally retains the **campaign-planning gate**, but not the old fixed four-video minimum, the old four creator-sequence prescriptions, or the old universal “5/5” CTA/gesture language. The active documents preserve a separate approval stage between fact research and scripts; the concrete campaign mix is currently defined product-by-product in an approved campaign proposal.

## 2. Current Active Campaign-Planning Section

> **Campaign Planning Gate — Separate Approval:** Only after the Fact-Record Completion Gate may a campaign plan be proposed. The plan must cite the current fact record and selected fresh framework card, identify its Product X-tested structure, record the real buyer problem, named buyer-psychology levers, proof-card source, and filming-day cart condition. ## 4. Recommended Ownership for Claude Project and Manus Research

Campaign planning does not belong entirely in fact-gathering research or entirely in generic script architecture. It is a distinct decision layer.

| Content | Recommended home | Why |
|---|---|---|
| Campaign-planning workflow, approval gate, required inputs, BOF inclusion, framework-selection logic, sequence principles, proof-card and cart checks | **Claude Project knowledge base** in a dedicated `CAMPAIGN_PLANNING_PROTOCOL.md` | These are reusable strategic decisions that Claude needs before deciding what scripts to write. |
| Exact product identity, label, directions, studies, reviews, comments, competitor facts, video links, current cart/offers | **Product-specific fact record / Manus research process** | These are live, source-bound inputs that change by product, seller, variant, and date. |
| Approved product-specific mix, sequence, asset test questions, and exceptions | **Product-specific campaign proposal** | A campaign should be earned from the relevant fact record and frameworks, not generated from a one-size-fits-all count. |
| Final script mechanics and sentence-level execution | **Six script-writing documents and selected framework/template** | Keeps campaign selection separate from drafting and quality review. |

## 5. Recommended Next Documentation Decision

Do **not** restore the entire legacy Step 12 verbatim. Create or approve a separate active `CAMPAIGN_PLANNING_PROTOCOL.md` that does the following:

1. Preserves the current hard gate: fact record complete → campaign plan → explicit user approval → scripts.
2. States the four-part initial BOF requirement with the current Type 4 Path A/Path B evidence boundary.
3. Defines whether the DryWater 10-asset sequence is the default initial-campaign template, a recommended extended launch, or solely a category-specific precedent.
4. Treats TOF-first and former five-creator sequences as source-informed planning defaults only when the current product/fact record supports them.
5. Requires a product-specific rationale for each asset, including framework, audience problem, psychology lever, proof source, and filming-day cart condition.

Until that separate document is approved, the active source hierarchy remains: **fact-only protocol for the gate; Master Context/source map for task order; current framework cards for format eligibility; and the approved product-specific campaign proposal for asset count and sequence.**
