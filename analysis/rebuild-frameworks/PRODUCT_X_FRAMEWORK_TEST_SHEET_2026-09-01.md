# Product X Framework Verification Sheet

**Purpose:** Let the creator judge the rebuilt framework mechanics before any real product, prior intelligence record, campaign language, or clinical claim is brought back into the system.  
**Status:** Review gate — not a script package and not product research.  
**Source basis:** The seven fresh framework records registered in `CLEAN_SLATE_ACTIVE_SOURCE_MAP.md`.

> **Testing convention:** `Product X`, `[viewer problem]`, `[benefit]`, `[ingredient]`, `[mechanism]`, `[competitor]`, and `[current offer]` are intentional placeholders. They are not claims and they do not represent a real product. The test asks one question only: **does the script visibly follow the proven structure in a way we would want to repeat?**

---

## How to Review This Sheet

For each example, ignore whether Product X is compelling. It is deliberately fictional. Review whether the framework has a distinct scroll-stopper, clear visual system, proper pharmacist role, direct viewer payoff, earned product timing, proof-card placement, and late CTA.

| Review question | Pass condition |
|---|---|
| Is the hook immediate? | The first visual, spoken, and text beat begins with the tension—not credentials or product description. |
| Is the format recognizably different? | The structure cannot be swapped with another framework without breaking the video’s core visual mechanic. |
| Does Product X arrive at the correct time? | It appears only after the framework has earned the viewer’s question, except where a source specifically requires an early real-product pivot. |
| Does the pharmacist add value? | The creator explains *why* the viewer should care in normal language instead of narrating a label. |
| Is proof visible but useful? | A claim-matched proof card follows the claim it supports; it does not replace the viewer payoff. |
| Is the CTA earned? | The cart comes after the product reason-to-care and only with verified filming-day context. |

## 1. BOF Type 1 — Short Apology-Reveal

**Framework job:** False negative → three reason-to-buy reminders → true offer payoff → urgency.  
**Target length:** 30–45 seconds.  
**Source card:** `BOF_APOLOGY_REVALIDATION_CARD_2026-09-01.md`

| Layer | Minimal Product X execution |
|---|---|
| **Visual hook** | Hold Product X beside a large red **“RETURNING IT?”** card; current cart is hidden. |
| **Text hook** | “WHY PEOPLE WERE RETURNING PRODUCT X…” |
| **Spoken script** | “I have to set the record straight about why people started returning Product X after I told them about it. It was not because it has **[feature/ingredient 1]**, which may help **[plain-language benefit 1]** when you are dealing with **[viewer problem 1]**. It was not because it has **[feature/ingredient 2]**, which may help **[plain-language benefit 2]** when you are dealing with **[viewer problem 2]**. And it definitely was not because of **[feature/ingredient 3]**, which matters when **[viewer payoff/problem 3]** is your goal. Those are exactly why it made sense in the first place. They were returning it because they paid full price before this **[real current offer/bundle]** showed up. If you still see that offer in the cart, I would not wait.” |
| **Product timing** | Physical product in hand at the hook; cart/offer only at the true-reason reveal. |
| **Proof behavior** | Three fast factual benefit overlays. No forced PubMed lesson; the speed/offer loop is the proof architecture for this warm-viewer asset. |
| **What makes it this framework** | The viewer expects product failure, then stays for each “not because” benefit, before the reveal that the real issue is overpaying. |

## 2. BOF Type 2 — Longer Apology With Pharmacist Breakdown

**Framework job:** Same apology-reveal loop, expanded by one meaningful pharmacist explanation per benefit.  
**Target length:** 55–75 seconds.  
**Source card:** `BOF_APOLOGY_REVALIDATION_CARD_2026-09-01.md`

| Layer | Minimal Product X execution |
|---|---|
| **Visual hook** | Product X + red return marker; creator looks concerned, then brings the product close. |
| **Text hook** | “I NEED TO EXPLAIN WHY I TOLD PEOPLE TO RETURN THIS.” |
| **Spoken script** | “I need to explain why people were returning Product X after I recommended it for **[viewer problem]**. It was not because of **[benefit 1]**. That matters because **[ingredient] works by [plain-language mechanism]**, which may help with **[specific viewer payoff]**. **[Proof card.]** It was not because of **[benefit 2]**—that is helpful when **[real use case]**. And it definitely was not because of **[benefit 3]**. All three are still the reason this product stood out. They returned it because they bought Product X alone before this **[real current bundle/offer]** appeared. If the cart still shows it, that is the version I would choose.” |
| **Product timing** | Product anchors the false-negative hook; full cart/bundle appears only at the payoff. |
| **Proof behavior** | One simple, claim-matched study/primary-source card follows the ingredient education line. It explains scope in the visual, not through defensive spoken narration. |
| **What makes it this framework** | It retains the same misdirection/reveal loop as Type 1; the pharmacist breakdown expands the middle rather than replacing the offer payoff. |

## 3. Type 4 — Scam Warning / Verified-Listing Education

**Framework job:** Protection tension → immediate authentic-product pivot → why viewers cared → exact verification tutorial → cart/comment close.  
**Target length:** 60–75 seconds.  
**Source card:** `TYPE4_SCAM_WARNING_REVALIDATION_CARD_2026-09-01.md`

| Layer | Minimal Product X execution |
|---|---|
| **Visual hook** | Four **real current** suspicious/counterfeit/seller-mismatch Product X listings appear with red circles; creator points to each. |
| **Text hook** | Red: “WATCH OUT FOR SCAMS” · white: “FROM A PHARMACIST” |
| **Spoken script** | “Fake. Fake. Fake. And fake. This is the real Product X. It took off because people wanted help with **[viewer problem]**, and **[ingredient] may help by [plain-language mechanism]**. **[Short proof card.]** That is exactly why you need to check who you are buying from. Open the product page, look for the official seller name, and make sure this **[visible verification marker]** is there before you check out. The verified Product X is in my cart—comment **[specific question]** if you want me to show you what to check.” |
| **Product timing** | The real physical product appears by approximately five seconds, immediately after the four-beat warning. |
| **Proof behavior** | Actual listing/seller images, official store screen, and verification location are primary proof. One brief ingredient proof card may support the “why it went viral” benefit, but cannot delay the protection tutorial. |
| **What makes it this framework** | Four-beat accusation, fast authentic pivot, buyer-protection education, and exact seller-check demonstration. |

> **Eligibility note:** If four genuine counterfeit/seller-mismatch listings do not exist, the literal “fake/scam” words are unavailable. Use the sourced **label-criteria path** or choose another framework; do not call an honest competitor fake.

## 4. Bundle Routine Walkthrough

**Framework job:** Solve “I do not know how to use this bundle” through a visible, reproducible routine.  
**Target length:** 45–75 seconds, depending on genuine item count.  
**Source card:** `BUNDLE_ROUTINE_WALKTHROUGH_REVALIDATION_CARD_2026-09-01.md`

| Layer | Minimal Product X execution |
|---|---|
| **Visual hook** | Open Product X bundle box/first texture directly against lens. |
| **Text hook** | “HOW TO USE THE PRODUCT X BUNDLE IN ORDER” |
| **Spoken script** | “If you bought the Product X bundle for **[viewer problem]** but do not know where anything goes, use it like this. **Step 1:** Product X Cleanser—start here to **[one direct role/payoff]**. **Step 2:** Product X Treatment—this is the step with **[ingredient]**, which may help by **[plain-language mechanism]**. **[Proof card.]** **Step 3:** Product X Moisturizer—finish with this to **[one direct role/payoff]**. That gives you a routine that is actually simple enough to repeat: cleanser, treatment, moisturizer. The whole set is in the cart if this is the routine you are building.” |
| **Product timing** | Physical bundle/first item at 0:00; one product, texture, use area, and payoff per step. |
| **Proof behavior** | Claim-matched visual beside the active step only. Never use a generic study dump or invent a routine order. |
| **What makes it this framework** | The step board and in-motion application let viewers save and recreate a coherent system. |

## 5. Category Scorecard / Expert Verdict

**Framework job:** Let viewers watch a pharmacist rate familiar real choices before the final linked recommendation.  
**Target length:** 35–55 seconds.  
**Source card:** `CATEGORY_SCORECARD_REVALIDATION_CARD_2026-09-01.md`

| Layer | Minimal Product X execution |
|---|---|
| **Visual hook** | Persistent header: “RATING [FAMILIAR CATEGORY] ON A SCALE OF 0–10.” |
| **Text hook** | Same persistent header; no product-name preamble. |
| **Spoken script** | **Off camera:** “[Recognizable option 1].” **Pharmacist:** “Four out of ten—fine for **[narrow role]**, but it leaves people with **[familiar limitation]**.” **Off camera:** “[Recognizable option 2].” **Pharmacist:** “Eight out of ten—good if **[use case]** is your main goal.” **Off camera:** “Product X.” **Pharmacist:** “Ten out of ten for **[viewer goal]** because it combines **[direct benefit]** with **[ingredient/product-role reason]**. **[Proof card.]** That is why it is the one I would look for in the cart.” |
| **Product timing** | One current item/prompt/score at a time. Product X receives the final major verdict. |
| **Proof behavior** | A simple evidence card follows the final ingredient/clinical statement; the physical package or exact listing supports product facts. |
| **What makes it this framework** | Off-camera prompt → immediate numerical reaction → one direct viewer reason. Earlier scores are meaningful but do not climb predictably. |

## 6. Do/Don’t Contrast

**Framework job:** Correct real viewer mistakes through an equal red **Never** / green **Always** substitution board.  
**Target length:** 20–35 seconds.  
**Source card:** `DO_DONT_CONTRAST_REVALIDATION_CARD_2026-09-01.md`

| Layer | Minimal Product X execution |
|---|---|
| **Visual hook** | Red/green 2×2 board: “4 THINGS TO NEVER / ALWAYS DO FOR [VIEWER PROBLEM].” |
| **Text hook** | Same title; the next green answer remains blank until the spoken turn. |
| **Spoken script** | “Never **[specific mistake 1]**. Always **[direct replacement 1]** because **[plain-language reason]**. Never **[specific mistake 2]**. Always **[direct replacement 2]** so you are not making **[same problem]** worse. That is why I look for **[Product X role/ingredient]** when people are trying to **[viewer goal]**—it can help with **[direct, qualified benefit]**. **[Proof card.]** Product X is in the cart if you are building that routine.” |
| **Product timing** | Pharmacist works through one paired red/green substitution at a time. Product X appears only after the education. |
| **Proof behavior** | A visual proof card supports any ingredient/mechanism claim at the late product bridge. |
| **What makes it this framework** | Every Always instruction directly replaces the paired Never behavior. It is a correction grid, not a list of disconnected tips. |

## 7. Numeric Scorecard — Execution Variation

**Framework job:** Use a persistent continuous 1–10/0–10 visual scale as the scoring language for a Category Scorecard.  
**Target length:** 30–50 seconds.  
**Source card:** `NUMERIC_SCORECARD_VARIATION_REVALIDATION_CARD_2026-09-01.md`

| Layer | Minimal Product X execution |
|---|---|
| **Visual hook** | “RATING [FAMILIAR CATEGORY] ON A SCALE OF 1–10,” above a fixed green-to-red number line. |
| **Text hook** | Header and number line persist; each real option gets an active marker. |
| **Spoken script** | **Off camera:** “[Real option 1].” **Pharmacist:** “Six out of ten—useful for **[narrow role]**, but not enough if your goal is **[viewer goal]**.” **Off camera:** “[Real option 2].” **Pharmacist:** “Three out of ten if **[familiar limitation]** is the trade-off.” **Off camera:** “Product X.” **Pharmacist:** “Nine out of ten for people who want **[direct payoff]**. It uses **[ingredient/product distinction]**, which may help by **[plain-language mechanism]**. **[Proof card.]**” |
| **Product timing** | Product X remains last; score order before it is meaningful rather than a forced 1-to-10 climb. |
| **Proof behavior** | Same scoped final-claim proof behavior as Category Scorecard. |
| **What makes it a variation** | The continuous number-line visual changes the feel; the off-camera prompt/immediate expert verdict remains the parent framework. |

## 8. Best-Last List — Execution Variation

**Framework job:** Build retention through a visible 3–5 item path whose final slot answers a real gap left by earlier choices.  
**Target length:** 25–45 seconds.  
**Source card:** `BEST_LAST_LIST_REVALIDATION_CARD_2026-09-01.md`

| Layer | Minimal Product X execution |
|---|---|
| **Visual hook** | Vertical list: “5 WAYS PEOPLE TRY TO [VIEWER GOAL]—BUT #5 MATTERS MOST.” The #5 slot is blank. |
| **Text hook** | Same header and unresolved #5 space. |
| **Spoken script** | “**Number 1:** [real familiar approach]—helpful for **[narrow role]**. **Number 2:** [real familiar approach]—good when **[use case]**. **Number 3:** [real familiar approach]—but it still leaves out **[core gap]**. **Number 4:** [real familiar approach]—useful, but not a complete answer if you want **[viewer goal]**. **Number 5:** Product X. This is the one I would look at because **[direct benefit]**, and **[ingredient/product role] may help by [plain-language mechanism]**. **[Proof card.]** If you still see it in the cart, that is the one I would start with.” |
| **Product timing** | Product X is withheld until the blank #5 reveal. Earlier items are real, familiar approaches—not filler designed to make Product X win. |
| **Proof behavior** | Show one scoped card after the final pharmacist mechanism/benefit. |
| **What makes it a variation** | The visible unfinished final list slot creates the retention loop; this is not a generic countdown or a second Category Scorecard. |

## Review Decision

Approve, revise, or reject each structure **before** it is used with a real product. If a framework passes, the next task is not script writing: it is a fresh fact-only product record and campaign plan that proves the framework-product fit.

| Framework | Decision to make |
|---|---|
| BOF Type 1 | Does the three-benefit → current-offer payoff loop feel fast and sales-oriented enough? |
| BOF Type 2 | Does the pharmacist explanation add value without slowing the apology/reveal mechanism? |
| Type 4 Scam Warning | Does the protection/tutorial sequence preserve the high-tension Riva-style execution? |
| Bundle Walkthrough | Does the repeated Step → show → explain → demonstrate loop make a bundle easier to buy/use? |
| Category Scorecard | Does the prompt → instant score → reason rhythm feel like the original expert verdict source? |
| Do/Don’t Contrast | Does each equal-column substitution feel genuinely paired and practical? |
| Numeric Scorecard | Does the scale create a useful visual variation without turning into a predictable countdown? |
| Best-Last List | Does the blank final slot create an earned reason to wait for the final answer? |
